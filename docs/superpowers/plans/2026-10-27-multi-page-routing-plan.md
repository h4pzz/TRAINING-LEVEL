# План реалізації: Багатосторінковий SPA Router, розділення «Бланки / Форми» та контроль доступу (RBAC)

**Дата:** 27 жовтня 2026 р.  
**Специфікація:** [2026-10-27-multi-page-routing-design.md](file:///d:/WIBECODING\TRAINING%20LEVEL\docs\superpowers\specs\2026-10-27-multi-page-routing-design.md)  
**Ціль:** Перевести монолітний додаток на багатосторінковий SPA роутер (HTML5 History API) з чистими URL, розділити розділ на чисті «Бланки» (`/blanks`) та інтерактивні «Форми» (`/forms`), а також забезпечити строгий контроль доступу за ролями (`CREW`, `OFFICE`, `INSTRUCTOR`, `ADMIN`).

---

## Завдання 1: Серверний SPA-Fallback (`server.js`)

- [ ] **1.1 Оновлення обробника маршрутів у `server.js`:**
  - Додати розпізнавання чистих URL-шляхів без розширення файлу (наприклад, `/dashboard`, `/flight-crew`, `/cabin-crew`, `/training-flights`, `/blanks`, `/forms`, `/settings`, `/portal`).
  - Для цих маршрутів віддавати `index.html` (HTTP 200, UTF-8, no-cache), дозволяючи клієнтському роутеру самостійно ініціалізувати необхідний вигляд.
  - Зберегти коректну віддачу статичних файлів (`.css`, `.js`, `.png`, `.jpg`, `.svg`, `.json`, `.pdf`).

## Завдання 2: HTML-розмітка та розділення розділів (`index.html`)

- [ ] **2.1 Оновлення бічного меню навігації (Sidebar):**
  - Додати атрибути `data-route` до пунктів навігації.
  - Розділити пункт «Бланки» на два окремих елементи:
    - `Бланки` (`/blanks`, іконка `printer`, id `nav-btn-blanks`).
    - `Форми` (`/forms`, іконка `file-edit`, id `nav-btn-forms`).
  - Оновити порядок пунктів:
    1. Аналітика (`/dashboard`)
    2. Льотний екіпаж (`/flight-crew`)
    3. Кабінний екіпаж (`/cabin-crew`)
    4. Тренувальні польоти (`/training-flights`)
    5. Бланки (`/blanks`)
    6. Форми (`/forms`)
    7. Налаштування (`/settings`)
    8. Мій кабінет (`/portal`)
- [ ] **2.2 Створення панелі «Бланки для друку» (`#view-blanks`):**
  - Виділити в `#view-blanks` каталог стандартизованих чистих PDF-бланків.
  - Категорії вкладок: *Льотний екіпаж*, *Кабінний екіпаж*, *Загальні форми UH*.
  - Пошук за назвою чи кодом бланка.
  - Дії для карток бланків: `[ Переглянути PDF ]`, `[ Завантажити ]`, `[ Друк ]`.
  - Модальне вікно / форма завантаження нових PDF бланків для адміністратора.
- [ ] **2.3 Оновлення панелі «Форми» (`#view-forms`):**
  - Залишити виключно генеративні та інтерактивні відомості (вибір пілотів, автопідтягування дат кваліфікацій з бази даних, попередній перегляд A4).
  - Вкладка Конструктора форм для налаштування нових шаблонів.
- [ ] **2.4 Підключення скрипта `js/router.js`:**
  - Підключити `<script src="js/router.js?v=0.8.0"></script>` перед `app.js`.

## Завдання 3: Модуль клієнтського роутера (`js/router.js`)

- [ ] **3.1 Таблиця маршрутів (Route Map):**
  - Визначення відповідності URL-шляхів до назв view, заголовків сторінок (`document.title`) та мінімально необхідних ролей.
- [ ] **3.2 Функція переходу `navigateTo(path, replace)`:**
  - Оновлення адресного рядка через `history.pushState()` / `replaceState()`.
  - Перевірка прав доступу через `resolveAllowedRoute(path)`.
  - Перемикання класів `.active` на `.view-panel` та `.nav-item`.
  - Виклик відповідної функції рендерингу (через `switchView`).
- [ ] **3.3 Обробник події `popstate`:**
  - Забезпечення коректної роботи кнопок браузера «Назад» / «Вперед».
- [ ] **3.4 Перехоплення кліків на посилання та кнопки меню:**
  - Делегування кліків для елементів із `data-route` або `data-view`.
- [ ] **3.5 Router Guards (Захист маршрутів):**
  - Якщо роль `CREW` $\rightarrow$ блокувати перехід на будь-які шляхи, крім `/portal`, з автоматичним редиректом на `/portal`.
  - Якщо роль `OFFICE` або `INSTRUCTOR` $\rightarrow$ блокувати `/settings` із редиректом на `/dashboard`.
  - Збереження чернеток (active input drafts) під час переходів між маршрутами.

- [ ] **4.1 Підтримка ролі `OFFICE` у Тренувальних польотах (`/training-flights`):**
  - При вході під роллю `OFFICE`:
    - Автоматично активувати вкладку «Архів польотів за місяцями» (`archive`).
    - Приховати кнопку перемикання на внесення нового польоту (`#btn-flights-tab-entry`).
    - Приховати кнопку «Імпорт сканів журналів (ШІ)» (`#btn-import-scans-ai`).
    - Приховати кнопки редагування (`EDIT`) та видалення (`DELETE`) в модальних вікнах деталей польотів.
    - Додати інформаційний бейдж: «Режим перегляду (Офіс)».
- [ ] **4.2 Розділення логіки рендерингу `renderBlanks()` та `renderForms()`:**
  - Створити окрему функцію `renderBlanks()` для каталогу чистих PDF-бланків.
  - Сфокусувати `renderForms()` на генерації звітів із вибіркою екіпажу та автозаповненням з бази.
- [ ] **4.3 Синхронізація сесії та роутера при логіні/логауті:**
  - Після `executeLogin()` викликати `navigateTo('/portal')` для `CREW` та `navigateTo('/dashboard')` для адміна/інструктора/офісу.
  - При виході з системи (`handleLogout()`) коректно повертати на головну.

## Завдання 6: Верифікація та тестування (End-to-End)

- [ ] **6.1 Тестування прямого відкриття за посиланням (Direct URL & F5):**
  - Перевірити оновлення сторінки (F5) на `/flight-crew`, `/training-flights`, `/blanks`, `/forms`, `/settings`, `/portal`.
- [ ] **6.2 Тестування історії браузера:**
  - Перевірити переходи кнопками «Назад» та «Вперед».
- [ ] **6.3 Тестування ролі `CREW` (наприклад, Алекса Сергій):**
  - Вхід у систему $\rightarrow$ відкривається `/portal`.
  - У меню відображається тільки «Мій кабінет».
  - Спроба перейти на `/flight-crew` чи `/settings` $\rightarrow$ спрацьовує редирект на `/portal`.
- [ ] **6.4 Тестування ролі `OFFICE`:**
  - Відкриття `/training-flights` $\rightarrow$ доступний тільки архів, кнопки внесення/редагування/видалення приховані.
  - Відкриття `/settings` $\rightarrow$ редирект на `/dashboard`.
- [ ] **6.5 Тестування ролі `INSTRUCTOR` та `ADMIN`:**
  - Перевірити повноцінне внесення польоту та роботу з бланками/формами.
  - Перевірити збереження введених даних польоту при випадковому переході в інший розділ і поверненні назад.
